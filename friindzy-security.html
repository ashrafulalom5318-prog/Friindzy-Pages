01 — Principles

Security Principles

Friindzy aims to apply reasonable security practices throughout the design, development, deployment, and operation of the Service.

Our security approach is based on principles such as:

  • Minimizing unnecessary access to user information.
  • Protecting authentication credentials and sensitive configuration.
  • Using secure communication mechanisms where appropriate.
  • Limiting access to systems and information based on operational need.
  • Keeping software and dependencies reasonably maintained.
  • Monitoring for operational and security problems where appropriate.
  • Providing users with controls for managing their account and data.
02 — Accounts

Account Security

Account credentials are an important part of protecting access to Friindzy.

Where authentication is provided, Friindzy may use authentication mechanisms and access controls intended to prevent unauthorized access.

You should use a strong, unique password where passwords are used, avoid sharing authentication credentials, and secure the device from which you access Friindzy.

If you believe that someone has obtained unauthorized access to your account, take reasonable steps to secure the account and contact Friindzy through the available support channel.

03 — BYOK

API Key Security

Friindzy may support Bring Your Own Key (“BYOK”), allowing users to connect API credentials from supported AI providers.

API keys can provide access to third-party services and may be linked to usage quotas or billing. They should therefore be treated as sensitive authentication credentials.

  • Do not publish API keys in public repositories.
  • Do not share API keys through screenshots or public posts.
  • Do not use keys that belong to another person without authorization.
  • Revoke or rotate a key if you believe it has been exposed.
  • Review the security controls provided by the relevant AI provider.

07 — Access

Access Controls

Access to systems and information should be limited according to operational requirements and the principle of least privilege.

Administrative access may be protected using authentication and other security controls appropriate to the environment.

We may review access, permissions, logs, or other operational information when reasonably necessary to maintain security, investigate incidents, or operate the Service.

08 — Content

Files & User Content

Friindzy may process files, images, documents, source code, prompts, and other content submitted by users.

Access to stored content should be limited to the systems and services necessary to provide the requested functionality, subject to the actual architecture and applicable third-party processing.

Friindzy may maintain technical or security logs to operate the Service, diagnose failures, detect abuse, investigate security incidents, and improve reliability.

11 — Maintenance

Updates & Vulnerability Management

We may periodically update the Friindzy application, server components, dependencies, security configurations, and related infrastructure.

Updates may include security patches, dependency updates, bug fixes, configuration changes, or improvements designed to reduce security risks.

Users should keep Friindzy updated to the latest supported version where updates are available.

12 — Incidents

Security Incidents

If we identify a security incident that affects information processed by Friindzy, we may investigate the incident and take reasonable steps to contain, remediate, and prevent recurrence.

Where notification is required by applicable law, we will provide notice through an appropriate channel and within the timeframe required by law.

Security incidents may involve investigation, temporary service restrictions, credential rotation, system changes, or other protective measures.

13 — Users

Your Security Responsibilities

Security is not solely the responsibility of the Service. You also play an important role in protecting your information.

  • Keep your account credentials private.
  • Protect your device with appropriate security controls.
  • Do not intentionally expose API keys or access credentials.
  • Use only API keys and accounts you are authorized to use.
  • Review third-party provider security and privacy documentation.
  • Keep the Friindzy application updated.
  • Report suspected security problems responsibly.
14 — Limitations

Security Limitations

No application, server, network, database, API, or electronic transmission can be guaranteed to be completely secure.

Accordingly, Friindzy does not promise absolute or perfect security. Security measures are intended to reduce risk, not eliminate every possible threat.

Third-party providers, devices, operating systems, networks, and services may introduce risks outside Friindzy's direct control.

15 — Reporting

Report a Security Issue

If you believe you have discovered a security vulnerability in Friindzy, please report it responsibly rather than publicly disclosing sensitive technical details.

When reporting a security issue, include enough information for us to understand and reproduce the problem, while avoiding unnecessary disclosure of personal information, credentials, API keys, or other secrets.
